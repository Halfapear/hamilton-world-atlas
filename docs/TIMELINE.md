## 时间规范

每份 Markdown 在标题下记录文档更新时间，新增记录记录实际事件日期。精确时刻有证据时才填写；只有日期时明确“具体时刻未记录”。

| 时间类型 | 含义 | 不可替代的其他时间 |
| --- | --- | --- |
| 文档更新时间 | 本页编辑、补记的时间 | 资料核验、测试完成、上线时间 |
| 来源发布时间 | 官方公告／报道自身的发布时间 | 收到截图、访问页面的时间 |
| 信息核验时间 | 实际读取并核对该来源的时间 | 文档更新、程序构建时间 |
| 构建／测试时间 | 对明确版本、哈希执行构建或检查 | 旧版本结果、新版未运行检查 |
| 提交／审核时间 | 平台回执、真实状态读取的时间 | 上传成功、部署成功与审核通过互不等同 |
| Git 提交时间 | 提交元数据记录的时间 | 编写、用户确认、测试或平台上线时间 |

统一示例：`文档更新：2026-11-06 16:38（北京时间，UTC+08:00）`。来源自身时区原样保留，并在面向用户的开票时间旁换算北京时间。韩国时间比北京时间快一小时。

不批量把所有日期替换为今天。原计划／旧交接保留，新增“历史补记”说明后续结果与权限变化。Git 提交只作为提交记录；文件 CreationTime／LastWriteTime 不作为历史事件依据。
